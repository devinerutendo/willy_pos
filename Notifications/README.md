# Notifications Module

This module provides a reusable notification system for inventory and sales alerts.
It includes:

- `Notification` records for in-app alerts
- `NotificationPreference` for per-user delivery preferences
- `NotificationLog` for delivery status tracking
- Celery tasks for batch alerts and scheduled notifications
- DRF API endpoints for fetching notifications and preferences

## Configuration

Add or update environment variables in your backend `.env` file:

```env
# Notification timing
NOTIFICATIONS_LAYBY_DUE_REMINDER_DAYS=3
NOTIFICATIONS_CASH_MISMATCH_THRESHOLD=10.00
NOTIFICATIONS_DAILY_SUMMARY_RECIPIENT_ROLE=MANAGER

# Email delivery
EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
DEFAULT_FROM_EMAIL=no-reply@inventory.local
EMAIL_HOST=smtp.example.com
EMAIL_PORT=587
EMAIL_HOST_USER=your-smtp-user
EMAIL_HOST_PASSWORD=your-smtp-password
EMAIL_USE_TLS=True
EMAIL_USE_SSL=False
EMAIL_TIMEOUT=10
```

## Celery schedule

The app is wired into `backend/Core/celery.py` with these scheduled tasks:

- `Notifications.tasks.daily_sales_summary_alert_task`
- `Notifications.tasks.layby_payment_due_reminder_task`
- `Notifications.tasks.layby_overdue_alert_task`
- `Notifications.tasks.cash_mismatch_alert_task`

Run Celery with the beat scheduler enabled to execute these on schedule.

## API Endpoints

The Notification API is mounted under:

- `/api/notifications/notifications/`
- `/api/notifications/preferences/`
- `/api/notifications/logs/`

These endpoints support fetching notification history and managing user delivery preferences.

## How it works

1. Alerts are created via `Notifications.services.create_notification(...)`.
2. `NotificationLog` entries are created for each delivery channel.
3. `Notifications.tasks.dispatch_notification_task` processes pending logs and marks them as sent or failed.
4. Scheduled alerts are generated by Celery tasks based on sales, layby, and reconciliation data.
